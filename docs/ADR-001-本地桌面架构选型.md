## 1. 背景与问题陈述 (Context & Problem Statement)

在第 1 轮原型中，系统通过 `src/server.js` 开启本地 HTTP 端口供浏览器标签页访问。用户与项目经理在第 2 轮明确提出：
> **使用软件本地方式而非网页端口前端交互，制作完整的启动程序等等符合软件开发流程的内容，具体架构经过你和子智能体讨论优劣后自己选定。**

为此，主智能体组织 3 个执行子智能体从各自专业领域（本地存储与外部 Agent CLI、桌面无边框视觉与 60fps 动效、主/渲染进程沙箱隔离与系统原生 API）对 4 种候选架构方案进行了全维度对比评审。

## 3. 最终选型决策 (Decision)

主智能体与 3 个子智能体一致决定采用 **方案 A：Electron 44.9 原生特权桌面架构（100% 同构对标 `SkillAtelier`）**，具体架构落地方案如下：

1. **零端口本地协议 (`src/main/assetProtocol.js` + `src/main/main.js`)**：
   - 注册 `app://local/` 特权协议，仅向沙箱渲染进程暴露 `src/renderer/`、`src/shared/` 与工作区 `crops/` 切片资源，拦截一切 `\0`、`..` 与符号链接越界访问。
2. **白名单 Preload IPC 桥接 (`src/main/preload.js` + `src/main/ipc.js` + `src/renderer/js/api.js`)**：
   - 通过 `contextBridge.exposeInMainWorld('papercard', ...)` 暴露唯一通信入口，严格校验 `contracts.IPC_CHANNELS` 定义的 19 个通道，集成系统原生 `dialog.showOpenDialog` 与 `clipboard.writeText`。
3. **完整的本地启动程序与桌面分发包 (`scripts/build-desktop.js` + `scripts/Launcher.cs`)**：
   - 构建 `release/PaperCardAtelier/PaperCardAtelier.exe` 独立桌面运行包（利用 NTFS 硬链接复用本机 Electron 44.9 核心运行时，兼顾独立运行与零磁盘冗余）。
   - 使用 Windows 内置 C# 编译器 (`csc.exe /target:winexe`) 在项目根目录编译生成原生无黑框启动器 `PaperCardAtelier.exe`，并配套生成 `启动工作台.cmd`、`PaperCardAtelier.vbs` 与 `创建桌面快捷方式.cmd`。
